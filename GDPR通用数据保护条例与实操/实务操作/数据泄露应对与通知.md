# 数据泄露应对与通知

> **核心问题**：发生个人数据泄露（personal data breach）后，企业应在何时、向谁、如何通知？

---

## 📋 基本概念

**数据泄露**（第 4(12) 条）：导致传输、存储或以其他方式处理的个人数据**意外或非法毁坏、丢失、篡改、未经授权披露或访问**的安全事件。

**两类通知义务**：
1. **通知监管机构**（第 33 条）：发现泄露后 **72 小时内**，除非泄露不可能对数据主体权利与自由构成风险；
2. **通知数据主体**（第 34 条）：泄露对数据主体权利与自由构成**高风险**时，须无不当延误地通知。

此外，**所有泄露**（无论是否需通知）均须记录在案（第 33(5) 条）。

---

## 📊 泄露响应流程

```
发现泄露事件（第一时间！）
    │
    ▼
第一步：遏制与评估（T+0）
    ├─ 切断攻击面、隔离受影响系统
    ├─ 评估泄露性质：涉及哪些数据、多少主体、是否加密
    └─ 判断可能性与严重性
    │
    ▼
第二步：风险判断
    ├─ 是否"可能"对数据主体构成风险？
    │     ├─ 否 → 记录即可（不通知）
    │     └─ 是 ▼
    │        通知监管机构（72 小时内）
    │           ├─ 是否"高风险"？→ 否 → 不通知数据主体
    │           └─ 是 → 通知数据主体（无不当延误）
    ▼
第三步：调查与记录
    ├─ 根因分析、影响评估
    ├─ 完善内部记录（泄露时间、事实、影响、应对措施）
    └─ 配合监管机构调查
    │
    ▼
第四步：改进
    ├─ 修复漏洞、更新安全措施
    └─ 复盘与培训
```

## 🔑 通知监管机构的要件（第 33 条）

| 要素 | 内容 |
|------|------|
| **时限** | 意识到泄露后 72 小时内（须"意识到"——及时发现机制很重要） |
| **延期** | 有正当理由无法按时完成的，须说明理由（分期提交信息） |
| **通知内容** | ① 泄露性质（涉及的数据类别与主体人数，尽可能）② 联系方式（DPO/联络点）③ 可能的后果 ④ 已采取/拟采取的应对措施 |
| **处理者义务** | 处理者发现泄露后须**立即告知控制者**（无 72 小时义务） |
| **记录义务** | 所有泄露均须记录：事实、影响、补救措施（供监管机构核查） |

---

## 🔑 通知数据主体的要件（第 34 条）

**触发条件**：泄露"可能对数据主体的权利与自由造成高风险"。

**通知内容**（用清晰、平实的语言）：
- 泄露的性质；
- 建议数据主体采取的缓解措施；
- 联络点（DPO 等）联系方式。

**无需通知的情形**（第 34(3) 条）：
- 已采取适当技术措施（如端到端加密且密钥未泄露），使数据不可读；
- 已采取后续措施确保风险不再可能实现；
- 通知需付出不成比例的过度努力（此时应改为公开声明或类似措施）。

---

## ⚠️ "风险"评估框架

| 风险等级 | 判断因素 | 行动 |
|----------|----------|------|
| **低** | 数据已加密、无敏感类别、影响有限 | 仅记录 |
| **中（可能）** | 个人数据被未授权访问，有滥用可能 | 通知监管机构 |
| **高** | 敏感数据（健康、财务）、大规模、可用于身份欺诈 | 通知监管机构 + 通知数据主体 |

**考虑因素**：数据敏感性（特殊类别更严重）、数量规模、可识别性（是否含身份信息）、滥用可能性（身份盗窃/欺诈风险）、缓解措施（是否加密/已补救）。

---

## 📊 泄露通知速查表

| 主体 | 何时通知 | 时限 | 谁通知 |
|------|----------|------|--------|
| 监管机构 | 泄露可能构成风险 | 意识到后 72 小时内 | 控制者（通过 DPO 等） |
| 数据主体 | 泄露构成高风险 | 无不当延误 | 控制者 |
| 控制者 | 处理者发现泄露 | 立即（无延迟） | 处理者 → 控制者 |
| 内部记录 | 所有泄露 | 及时 | 控制者/处理者 |

---

## 📝 落地建议

1. **事前**：制定泄露响应计划（IRP），明确分工（法务、安全、公关、DPO）；
2. **事中**：成立应急小组，24 小时内完成初步评估（是否需通知的初判）；
3. **文档**：泄露登记簿（breach register）持续更新；
4. **演练**：定期演练 72 小时通知流程，缩短实际响应时间；
5. **与 DPA/供应商联动**：在数据处理协议中约定处理者的泄露告知义务与时限。
