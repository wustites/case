# 数据主体权利响应流程

> **核心问题**：收到数据主体访问请求（DSAR）后，企业应当如何规范、按时地响应？

---

## 📋 基本概念

数据主体权利请求（Data Subject Request, DSR / Data Subject Access Request, DSAR）包括访问、更正、删除、限制、可携带、反对等全部第 12-22 条权利的行使。**响应时限（1 个月 + 可延 2 个月）与免费原则（原则上免费）是硬性合规要求**，逾期或违规收费均可能招致投诉与处罚。

---

## 📊 端到端响应流程

```
收到请求（邮件/表单/客服渠道）
    │
    ▼
第一步：识别与登记
    ├─ 确认请求是否属于 GDPR 权利请求（vs 一般客服咨询）
    ├─ 登记：请求类型、数据主体身份、接收时间、渠道
    └─ 启动计时（1 个月期限）
    │
    ▼
第二步：身份验证（必要时）
    ├─ 仅要求与风险相称的信息（避免过度索取）
    ├─ 高风险请求（删除/可携带）可加强验证
    └─ 无法验证身份 → 可拒绝，但须告知理由
    │
    ▼
第三步：检索与评估
    ├─ 跨系统检索数据主体相关数据（CRM、ERP、日志、备份）
    ├─ 评估请求类型对应的处理要求
    ├─ 检查是否有拒绝理由（明显无根据/过度重复/法定例外）
    └─ 涉及他人数据时进行脱敏/平衡
    │
    ▼
第四步：处理决定
    ├─ 支持 → 执行操作（提供副本/更正/删除/传输…）
    ├─ 部分支持 → 在可行范围内响应并说明
    └─ 拒绝 → 书面说明理由 + 告知投诉权利（第 77 条向监管机构申诉 + 第 78/79 条司法救济）
    │
    ▼
第五步：交付与留痕
    ├─ 以结构化、常用格式交付（可携带权须机器可读）
    ├─ 记录全流程（问责制证据）
    └─ 通知第三方（如数据已共享，技术可行时通知更正/删除）
```

---

## 🔑 关键时限与规则

| 要素 | 规则 | 说明 |
|------|------|------|
| **基础时限** | 1 个月 | 自收到请求起算 |
| **可延长** | 最多再延 2 个月 | 请求复杂或请求量大时；须在 1 个月内告知延期及理由 |
| **工作日 vs 日历日** | 以"收到请求之日起 1 个月"为准 | 建议按日历日计算并预留缓冲 |
| **费用** | 原则上免费 | 仅"明显无根据或过度（尤其重复）"时可收合理费用或拒绝，且须能证明 |
| **身份验证** | 必要且相称 | 不得要求超出风险所需的信息 |
| **拒绝告知** | 收到后 1 个月内 | 告知理由 + 数据主体申诉/司法救济权利 |

---

## ⚠️ 常见风险点

| 风险 | 后果 | 规避 |
|------|------|------|
| 逾期未响应 | 投诉 + 处罚 | 工单系统自动计时、预警 |
| 过度索取身份材料 | 被认定违规 | 按风险分级验证 |
| 擅自收费 | 违反免费原则 | 收费仅限"明显无根据/重复"且留档 |
| 响应不完整（漏系统） | 访问权被认定未满足 | 建立全量数据地图 |
| 未通知第三方更正/删除 | 义务履行不完整 | 共享数据台账 + 联动通知 |

---

## 📝 各权利请求的响应要点

| 请求类型 | 响应要点 |
|----------|----------|
| **访问** | 提供处理信息 + 数据副本；副本可要求合理费用（仅"明显过度"时） |
| **更正** | 更正 + 通知接收方（第 19 条） |
| **删除** | 检查第 17(3) 条例外；通知接收方；公开传播数据须通知其他处理者 |
| **限制** | 仅存储，暂停其他处理，直至争议解决 |
| **可携带** | 结构化、常用、机器可读格式；技术可行时直接传输至另一控制者 |
| **反对** | 合法利益场景须证明压倒性理由；直接营销场景立即停止 |
| **自动化决策** | 提供人工干预、表达观点、质疑决策的机制 |
