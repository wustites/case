# 企业合规落地清单

> **核心问题**：企业（尤其是面向欧盟市场的中小企业）如何系统落地 GDPR 合规？

---

## 📋 基本概念

GDPR 合规不是一次性项目，而是持续的治理机制。本清单按"识别 → 设计 → 执行 → 验证"四阶段组织，可作为企业合规启动的检查表。

---

## 📊 四阶段落地清单

### 第一阶段：识别与摸底

```
□ 确认是否落入 GDPR 适用范围（设立地 / 向欧盟提供服务 / 监控欧盟用户）
□ 梳理数据处理活动清单（收集哪些数据、来源、目的、存储位置）
□ 识别数据流：内部系统、外部供应商、跨境传输路径
□ 评估现有处理的法律依据是否充分
□ 识别高风险处理（敏感数据、大规模画像、儿童数据）
```

### 第二阶段：制度与组织设计

| 事项 | 要点 |
|------|------|
| **治理架构** | 指定合规负责人；符合条件时任命 DPO 并公开联系方式 |
| **隐私政策** | 按第 13-14 条更新：控制者身份、目的、依据、权利、投诉渠道 |
| **同意机制** | 单独、明确、可撤回的同意流程 + 同意记录留痕 |
| **数据地图** | 建立处理记录（第 30 条）并持续更新 |
| **供应商管理** | 处理者清单 + 逐家签署 DPA（数据处理协议） |
| **跨境合规** | SCC/BCR 签署 + 传输影响评估（TIA） |
| **政策文件** | 数据保留政策、泄露响应计划（IRP）、员工隐私手册 |

### 第三阶段：技术与执行

```
□ 落实"设计与默认保护"（最小化默认配置、隐私增强技术）
□ 实施安全措施（第 32 条）：加密、访问控制、日志审计、渗透测试
□ 建立 DSAR 响应流程（1 个月时限 + 免费原则）
□ 高风险处理启动 DPIA（第 35 条）
□ 部署泄露检测与 72 小时通知机制
□ 员工培训（至少每年一次 + 新员工入职）
□ 儿童数据处理合规（年龄验证、监护人同意，如适用）
□ Cookie 与跟踪技术合规（ePrivacy 指令：告知 + 同意）
```

### 第四阶段：验证与持续改进

```
□ 定期合规审计（自评或第三方）
□ 监控监管机构指南（EDPB、所在国 DPA）与判例更新
□ 重大业务变更时重新评估（新产品、新处理活动）
□ 演练泄露响应与 DSAR 流程
□ 年度复评跨境传输安排（TIA 更新）
□ 保留全部合规证据（问责制文档）
```

## 📊 常见行业重点

| 行业 | 重点风险处理 | 特别要求 |
|------|--------------|----------|
| 电商/零售 | 订单数据、营销画像 | 同意管理、跨境传输、Cookie 同意 |
| 金融 | 账户数据（敏感） | DPIA、严格安全措施、反欺诈处理 |
| 医疗健康 | 健康数据（特殊类别） | 第 9 条例外审查、高门槛同意 |
| 广告/营销科技 | 行为画像、实时竞价 | 合法依据（同意优先）、透明性 |
| SaaS/云服务 | 处理者角色、多租户 | DPA、sub-processing 管理、审计权 |
| 人力资源 | 员工数据、监控 | 成员国劳动法叠加合规 |

---

## ⚠️ 常见合规误区

| 误区 | 正确做法 |
|------|----------|
| 只更新隐私政策就算合规 | 政策只是冰山一角，处理记录/DPA/DSAR 流程同等重要 |
| 认为不设立实体就不适用 GDPR | 第 3(2) 条域外适用：向欧盟用户提供服务即可能触发 |
| 用"合法利益"兜底所有营销 | 须逐场景做利益平衡评估并留档 |
| 忽略供应商数据处理 | 处理者违规，控制者同样可能被追责 |
| 跨境只签 SCC 不做 TIA | Schrems II 后 TIA + 补充措施是执法重点 |

---

## 📝 落地优先级建议（资源有限时）

1. **先做数据地图**：没有清单无从合规；
2. **再补合法性**：同意机制 + 合法依据评估；
3. **然后堵漏洞**：DPA、跨境传输工具、安全措施；
4. **最后建机制**：DSAR 流程、DPIA、培训、审计。
