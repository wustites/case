## 📁 通用结构

每个知识库遵循统一结构，便于检索与维护：

```
主题/                     ← 一个法律主题一个目录，目录名即知识库名
├── README.md             ← 项目说明、适用人群、内容速查、关键时间线、完整文件索引
├── 法律法规/             ← 法律条文、司法解释、立法背景
├── 实务操作/             ← 操作流程、合规指引、风险分析
├── 案例参考/             ← 典型案例与判例分析
└── 参考资料/             ← 官方资料、文献、报告
```

核心约定（完整维护流程见 [`CONTRIBUTING.md`](CONTRIBUTING.md)）：

| 约定 | 说明 |
|------|------|
| **分类固定** | 仅使用上表四个分类目录；不新增同级目录，避免结构漂移 |
| **文件命名** | 文件名即标题（中文、无序号前缀），同一主题内不重名 |
| **索引完整** | 每个知识库的 `README.md` 必须以表格列出该库**全部**内容文件，新增文件时同步更新索引 |
| **文末章节** | 内容文件统一以 `## 🔗 相关文件`（库内相对链接，可跨分类）与 `## 📄 许可` 结尾 |
| **链接形式** | 一律使用**相对路径** Markdown 链接，保证本地与 GitHub 均可点击 |
| **免责声明** | 各库 `README.md` 必须包含免责声明；内容文件可按需补充 |

提交前可运行 `python3 scripts/validate_repository.py`，一次检查标准目录、专题索引、统一页脚和 Markdown 本地链接；GitHub Actions 会在推送和拉取请求中执行同一校验。
